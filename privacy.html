1. Overview and scope

This Privacy Policy explains how the Personal Google Drive Sync Client ("the Application", "we", "us") accesses, uses, stores, shares and deletes information when it connects to Google Drive. The Application is a personal, non-commercial OAuth client ID and client secret used together with rclone, an open-source command-line file-transfer tool.

The Application is operated by an individual developer and is designed for the developer's own, single Google Drive account. It is not offered, distributed or marketed as a public service, it has no hosted backend server, and it does not create user accounts. All processing takes place on the user's own device, directly between that device and Google's servers.

Google API Limited Use disclosure. The Application's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. In particular, Google user data is used only to provide and improve the user-facing file-sync features described in this policy.

2. Who is responsible (data controller)

The Application is published by an individual developer:

  • Publisher: Korbinian Pöppel (individual developer)
  • Contact: GitHub Issues

Because the Application is used solely by its publisher with the publisher's own Google account, the publisher is also the only data subject whose Google data is accessed. No third-party end users are served by this Application.

3. Information the Application accesses

When you authorize the Application through Google's OAuth 2.0 flow, the Application requests access to the following Google API scopes and the data they cover:

Scope What it allows
https://www.googleapis.com/auth/drive Read, create, modify and delete files and folders in Google Drive, so files can be synchronized.
https://www.googleapis.com/auth/drive.metadata.readonly Read file and folder metadata (names, sizes, MIME types, modification dates, IDs, parents) to compare and reconcile files.
https://www.googleapis.com/auth/docs Read and write Google Docs documents where required for document synchronization/export.
Basic profile (userinfo.email, openid) Identify which Google account is connected, so the correct account and quota are used.

In practice, this means the Application can access the files, folders, Google Docs documents and associated metadata in the authorized Google Drive account. It accesses only the account the user explicitly authorizes; it does not access any other Google account.

The Application does not collect names, addresses, phone numbers, payment information, passwords, contacts, calendars, location data, or health information. It does not use cookies, advertising identifiers, analytics SDKs or tracking pixels.

4. How the information is used

Google user data is used exclusively to provide the file-transfer features the user requests, specifically to:

  • List and compare files and folders between the local device and Google Drive;
  • Upload, download, copy, move, rename and delete files the user selects;
  • Export or import Google Docs documents when configured to do so;
  • Verify that a transfer completed successfully and report errors to the user.

The Application does not use Google user data for advertising, marketing, profiling, user tracking, credit-worthiness or lending decisions, and does not use it to train machine learning or artificial-intelligence models.

5. Storage of information

The Application has no server and no database. No Google user data, file contents or metadata is transmitted to, copied to or stored by the publisher or any third party.

The only information stored is kept locally on the user's own device:

  • OAuth credentials/tokens issued by Google, stored in rclone's local configuration file so the user does not have to sign in on every run. These tokens are protected by the operating-system file permissions of the device; where rclone's configuration encryption is enabled, they are additionally encrypted with a password chosen by the user.
  • rclone configuration and logs, which may contain the remote name, file paths and transfer statistics. These remain on the local device and may be deleted by the user at any time.
  • Files being synchronized, which are written to the local destination or temporary directories chosen by the user.

6. Sharing and disclosure

We do not sell, rent, trade or share Google user data with any third party. We do not disclose Google user data to advertisers, data brokers, analytics providers or any other organization.

The only transfers that occur are:

  • Between the user's device and Google, as required to perform the requested file operations using Google's own API endpoints.
  • To storage destinations the user explicitly configures (for example, a local disk, an external drive, or another remote the user has already set up in rclone). The user controls those destinations.

No human reads Google user data, and no Google user data is transferred to third parties except as necessary to provide or improve the user-facing features, as required for security or to comply with applicable law, or as part of a merger/acquisition with prior notice to the user.

7. Data retention and deletion

  • Google user data is accessed on demand and is not retained by the publisher. It exists only transiently in local memory/files while a transfer is running.
  • OAuth tokens remain stored locally until the user removes them. The user can delete the rclone remote (for example, with rclone config delete <remote>) or delete the rclone configuration file.
  • The user can revoke the Application's access to the Google account at any time at https://myaccount.google.com/permissions (Google Account → Security → Third-party apps & services). Revoking access immediately invalidates the stored tokens.
  • Files already transferred to a local or other destination are controlled by the user and can be deleted by the user using normal file operations.

10. Security

The Application relies on Google's OAuth 2.0 framework and TLS/HTTPS for all communications with Google. Tokens are stored locally under the operating system's file-permission controls and, optionally, rclone's configuration encryption. No method of transmission or storage is completely secure; users are responsible for securing their own devices and for protecting any client secret, token or configuration-encryption password.

11. Children's privacy

12. International users
